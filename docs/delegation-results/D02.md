## Decisiones implementadas

- Se añadieron lectura de sesión, paginación de sesiones, intentos y mensajes.
  Las lecturas por tarea validan cursores opacos contra sesión y dirección;
  aun al pedir `backward`, los elementos vuelven en orden ascendente.
- `saveTaskMutation` guarda reserva, job normalizado, sesión, mensaje y evento
  en una transacción. Un replay igual devuelve el snapshot original; otra
  operación o contenido con la misma clave de tarea falla sin replay cruzado.
  El fingerprint SHA-256 solo usa operación y request normalizado, no IDs ni
  estado posterior.
- `saveInitialJobWithTaskMessageAndEvent` es la ruta aditiva para submit
  inicial: conserva la clave legacy opcional por workspace y confirma intento
  nuevo, mensaje y evento normalizado antes de devolverlo para publicar. No
  permite actualizar un ID existente. D03 la usa para submit inicial; D04 usa
  `saveTaskMutation` para continuaciones, retry y cola por tarea.
- Las reservas nuevas no se copian al índice legacy de jobs, que continúa
  delimitado por workspace y clave. Dos tareas pueden usar la misma clave nueva
  sin afectar `findJobByIdempotencyKey`.
- Tras la revisión se cerró la ruta de sobrescritura: una mutación nueva exige
  que `input.job.id` no exista, después de comprobar un replay legítimo y antes
  de limpiar la clave legacy o escribir. La regresión conserva un intento READY
  (estado, payload, snapshot y lookup legacy), deja cero mensaje/evento/reserva
  tras el rechazo y permite usar la misma clave con un draft nuevo.
- `task_message_attempt_dispatches` impone un despacho por mensaje y comprueba
  pertenencia de mensaje, intento y sesión en la misma transacción. El `jobId`
  del mensaje permanece inmutable; no se ejecuta una cola.
- Las actualizaciones genéricas de mensajes no pueden retargetear destinatario,
  intención, objetivo, contexto ni identidad de proveedor. D03 dispone de un
  enriquecimiento específico set-once para identidad runtime desconocida.
